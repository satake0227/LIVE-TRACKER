# LIVE TRACKER

ライブの公演と複数のチケット申込を管理する、ビルド不要の静的Webアプリです。添付された初期版を拡張しています。

## すぐに試す

1. ZIPを展開し、`index.html`、`style.css`、`script.js`が同じフォルダにあることを確認します。
2. `index.html`をブラウザで開きます。うまく動かない場合は、このフォルダで `python3 -m http.server 8000` を実行し、`http://localhost:8000` を開いてください。
3. 「新規登録」から公演を登録します。申込を同時に登録するか選べます。公演詳細から申込を複数追加できます。

保存先はブラウザごとのlocalStorageです。同じ端末でもブラウザやURL（localhostと公開URLを含む）が異なるとデータは共有されません。ブラウザデータを消すと失われるため、「設定」から定期的にJSONを書き出してください。JSONには個人の申込情報が含まれます。復元は現在のデータをすべて置き換えるので、事前に書き出してください。自動通知・同期はありません。パスワードやカード番号は保存しないでください。

## 機能

- 公演ごとにアーティスト名を登録・編集・削除（アーティスト専用の独立した管理画面はありません）
- 1公演に複数の申込。区分、受付開始・締切、申込状況、当落、入金期限、支払日、カード引落日、合計金額、枚数、支払い状況、メモを記録
- ダッシュボード、月間カレンダー、公演詳細、申込一覧
- JSONバックアップと検証付き復元。添付された旧版の `live-tracker-v1` データを同じブラウザ・同じURLで引き継ぎます。旧版では存在しなかった項目は空欄です。

アーティスト名は公演ごとに保存します。同じアーティストの名前を一括変更する機能はありません。金額はチケット1枚の単価ではなく申込全体の合計です。期限切れの未対応の申込締切・入金期限はダッシュボードに残ります。

## 構成

- `index.html`：画面と入力フォーム
- `style.css`：表示とモバイル向け調整
- `script.js`：データ、画面描画、保存、バックアップ
- `OFFICIAL-INFO.md`：公式情報取得の設計と未実装範囲

主要なデータは `events`（公演）と `applications`（申込）の配列です。申込の `eventId` が公演を参照します。旧データの互換性のため保存キーは `live-tracker-v1` のままです。

## GitHubに公開する

1. GitHubにサインインし、New repositoryで新しいリポジトリを作成します。名前は例として `live-tracker`。公開・非公開は目的に応じて選択します。
2. リポジトリの「Add file」→「Upload files」で、このフォルダ**の中身**をアップロードし、Commit changesを押します。`index.html`がリポジトリのトップにあることを確認します。
3. Gitに慣れている場合は、代わりにこのフォルダで `git init`、`git add .`、`git commit -m "Initial LIVE TRACKER MVP"` を実行し、GitHubが表示する手順でリモートを追加してpushできます。

## Vercelに公開する

1. Vercelにサインインし、GitHub連携を許可します。
2. 「Add New」→「Project」から作成したGitHubリポジトリをImportします。
3. `index.html`がリポジトリ直下ならRoot Directoryはそのままにし、Framework PresetはOther、ビルドコマンドと出力ディレクトリは空欄のままDeployします。フォルダの中に置いた場合はそのフォルダをRoot Directoryに指定します。
4. 発行されたURLを開いて確認します。以後、連携済みブランチへのpushで自動デプロイされます。

Vercelへの公開はコードを公開する操作です。各利用者のlocalStorageは各ブラウザ内にあり、サイト運営者に自動送信されません。ただし端末共有者や同じオリジンのスクリプトから読める点に注意してください。開発時のデータを公開URLに移す場合は、元の画面からJSONを書き出し、公開URL側で読み込みます。

## アーティスト名で公演を検索する

新規登録でアーティスト名を入力して「公演候補を検索」を押すと、Ticketmaster Discovery APIの候補を表示します。これはアーティスト公式サイトの検索ではなく、Ticketmasterに掲載された情報です。公演が掲載されていない場合や、同名の別人の候補が出る場合があります。検索語はTicketmasterに送信されます。出典ページと日時、タイムゾーンを確認してから候補を反映してください。

公演名、開催日時または時間不明の開催日、会場、出典URL、および取得できた一般発売の開始・終了日時を入力欄に反映します。取得できない項目は推測せず、個人の申込・当落・支払い情報は変更しません。先行受付や当落発表はこのAPIから特定できないため手入力です。画面の開催日時は公演地の現地時刻として表示します。日本以外の公演も検索されるため、予定管理の際はタイムゾーンを確認してください。

検索を有効にするには、以下が必要です。

1. [Ticketmaster Developer](https://developer.ticketmaster.com/) に登録し、Discovery APIのキーを取得します。利用条件・必要な表示・レート制限を確認してください。
2. Vercelの対象プロジェクトの Settings → Environment Variables に `TICKETMASTER_API_KEY` を登録します。値は公開せず、GitHubに書き込まないでください。
3. 本プロジェクトをVercelへ再デプロイします。`api/search.js` がサーバー側でAPIを呼びます。Vercelの公開URLで検索を試してください。

`index.html` を直接開く方法や `python3 -m http.server` だけではサーバー側の検索機能は動きません。手入力は利用できます。APIキー未設定時や取得失敗時にはエラーが表示されます。APIの利用状況・プランやデータ提供範囲は変わる可能性があるため、公開前に提供元の条件を確認してください。
